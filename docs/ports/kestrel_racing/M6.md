## 1. The horizon haze (`racer/haze.zig`; option HAZE, key `q`)

Far faces blend toward the track's haze colour by DEPTH, as palette work: no per-pixel maths, no dithering.

- **Bands.** The depth key (1/8 unit, far 0 .. near 1023) picks one of 4 bands through a 1,024-entry table rebuilt only
  when R changes: none nearer than `start`/256 of R's distance (R x 8 units), the full `strength`/255 at R. A band is
  the nearest of the continuous blend (band b = strength x b / 4).
- **LUTs.** One 256-entry LUT a band: `project.build` maps a polygon's colour with one load (`haze.colour(key, c)`), so a
  face, its decals and a car (one key a car) change band whole. Cost: frame_cost +0.02-0.04 Mc a frame (Glacier race).
- **The pool.** Hazed colours live in the palette entries no ramp uses: 16 + 8 x max(ramps, 19) .. 255 (the track's ramps,
  then the cars' 12-18). Band 1 is each track colour's EXACT blend; bands 2-4 reuse an earlier entry within MERGE (a
  squared RGB distance of 192: the far colours converge on the haze) or take a new one while the pool lasts, else the
  nearest; a car colour never takes an entry (the nearest of the pool and itself). The pool is built for the shading in
  force (key i's FLAT / LIT / SOFT rebuild the look).
- **No seam.** The far ground (palette 4) and the backdrop (12-14) are blended at full strength, so the last band meets
  the ground beyond R.
- **The shadow.** A car shadow whose key is in a band is not drawn (the haze washes it out), and `shadow.darken` leaves
  pool entries alone (they are not ramps; with no pool the word path is M5's code, `darkenW(false)`).
- **The mood block.** Bytes 27-31 (M5's zero tail): haze RGB, start, strength; strength 0 = none and then the rest must be
  0 (trk.zig refuses BadMood, mood.py refuses on pack). Every M5 file reads as "no haze". Track Kit: `ktrk_haze`,
  `ktrk_haze_start`, `ktrk_haze_strength` (the mood panel's rows); `kit.py` refuses a haze whose face colours do not fit
  the pool (`mood.haze_room`).
- **The tracks.** Salt Flats: heat haze (228, 216, 192), start 112, strength 140 (26 face colours, 56 spare entries).
  Glacier Pass: overcast (202, 208, 216), start 96, strength 150 (34 of 64). Neon Docks (29 ramps: 8 spare for 48
  colours) and the 32X courses (30 ramps) have no room: no haze (the options screen says NONE, or NO ROOM for a file
  that asks for one).
- **Off.** No haze in the mood, the option, or key `q`: `haze.build` returns before touching anything; the palette, the
  LUTs (identity) and every index are M5's.

Shots (local, not committed): `racer_haze_<track>_<pose>.png` and `_off.png` from `racer_haze.mjs <dir>`.

### The gate (`apps/harness/racer_haze.mjs`, 4 lines)

- Haze OFF (key `q`): the 8 attract poses = **racer_tracks.mjs' M5 pins**, byte for byte (Salt Flats and Glacier Pass).
- Haze ON: every changed pixel moves from a track colour to a pool entry nearer the haze (Glacier: 10,584 pixels over the
  8 poses, 7,179 an exact band blend; Salt: 7,236 / 3,739); the bottom 16 view rows are untouched; palette 4 = the full
  blend; the views pinned; CPU = AFFINE; the race grid at R 8 changes the far view only; Neon Docks unchanged by `q`.
- `--break absent` (key N: built, never applied) and `--break near` (key P: every band one nearer) are caught.
- `racer_tracks.mjs` presses `q` after boot, so all its pins stay M5's (and the Python reference still matches).
- Native: `haze_test.zig` (7 tests: identity when off, band 1 exact, bands monotonic by depth and following R, no room on
  Neon, the mutants, the shadow's byte and word paths with a pool at every bottom), `trk_test.zig` (the haze bytes'
  refusals). Python: `test_racer_moodpanel.py` (pack / unpack, refusals, the kit's room check on Neon).

## 2. The perf pass

`node apps/harness/racer_m6_costs.mjs` (new: the flyby lap, the race at the grid and mid-race in each POV, per track;
`--hot <track>:<scene>` lists the top functions with the names twin, `tools/perf_names.sh`) and `tools/perf_audit.sh
racer` (with `--disk` and `--call` keys for the race views). Two cuts landed (below); the big finding is in the MODEL's
split, not the cart:

| scene (R 8, CPU fill, plain multiply twin) | total | cart | I$ term | FRESCO | total without I$ |
|---|---|---|---|---|---|
| Glacier, flyby | 1.55 | 0.57 | 0.26 | 0.70 | 1.29 |
| Glacier, race grid, far | 2.95 | 0.90 | 1.33 | 0.70 | 1.62 |
| Glacier, race grid, near | 3.29 | 1.06 | 1.52 | 0.70 | 1.78 |
| Glacier, mid-race, near | 3.30 | 0.93 | 1.65 | 0.70 | 1.65 |
| DXFOREST (local), race grid, far | 10.50 | 4.11 | 5.68 | 0.70 | 4.82 |
| DXBAY (local), mid-race, far | 8.69 | 2.94 | 5.03 | 0.70 | 3.65 |

- **The race's "+1.2 Mc over the flyby" is the model's instruction-cache term**, which grows with the race's code
  footprint (cars, physics, AI, HUD), not the cart's work: the cart adds 0.3-0.5 Mc. The board has already shown that
  term is not real here (M3: the oval race 60 fps where the total said 33; M5: Salt Flats race 60.3 fps where it said
  2.9-3.3 Mc). The figure WITHOUT the I$ term tracks the board: 1.6-1.8 Mc on our tracks (60 fps measured on Salt), and
  4.8 / 4.0 Mc at the DXFOREST / DXBAY grids against 25 / 33 fps measured (3.3-4 Mc a frame): still ~20 % high there,
  the plain multiply twin's share (the board runs `mulsh16` as one ZM-X instruction).
- **Glacier Pass' race needs no R cap**: 1.57-1.78 Mc without I$ in every POV, the same as Salt Flats, which runs 60 on
  the board. Its heaviest flyby pose (522, the cockpit before the tunnel) is 2.02 Mc total, 1.3-1.4 without I$.
- **Where the cart's cycles go** (DXFOREST grid, cart 4.11 Mc): the vertex loop of `project.build` (transform, outcodes,
  guard band, projection through the cache) 1.82 Mc; the span emitter and fill 0.8 Mc; `fx.rcp` 0.24; collect's face loop
  0.18; sort 0.06; cars 0.06; HUD + minimap 0.01. On our tracks the same shape at a quarter of the size.
- **Cut 1: a trapping store per polygon** (perf_audit: `misaligned`, DXFOREST's grid 899 of 1,296 accesses a frame,
  Glacier's 107 of 199, the title 111 of 155). `project.build` and `push` returned `?u16`: a 4-byte value at align 2,
  written through the caller's stack slot with one i32 store, which TRAPS on ZIGGY when the slot is 2 mod 4 (~210
  cycles, emulated). They now return a u32 with a NONE sentinel (`project.NONE`): no misaligned access is left in any
  view perf_audit runs (title, Glacier grid, DXFOREST grid). frame_cost on the DXFOREST grid 10.32 -> 10.08 Mc, the
  Glacier grid (haze off) 2.90 -> 2.86; on the board ~899 x 210 = ~0.19 Mc a frame on the 32X courses. Same pixels.
- **Cut 2: the HUD reprints only its changed character cells** (`hud.changed`): a line whose text changed was reprinted
  whole (40 glyphs, 2,560 bytes) every frame the race clock ticks; now the changed columns only (the 8 x 8 font's cells
  give the same pixels; the race's HUD hashes are unchanged). Small (~0.01-0.02 Mc), but it is the "only modify what
  changes" rule.
- **Tried and reverted:** projecting a vertex on first use by a kept face instead of on transform (`xform.screen`): the
  same pixels, but the 32X grid's cart went 4.11 -> 4.17 Mc and Glacier's 0.90 -> 0.89: nearly every transformed vertex
  is projected anyway (the PVS is already per yaw bucket), so the extra stamp check costs what it saves.
- **Not changed:** perf_audit's other findings are its byte-loop heuristics on the per-vertex and per-span loops (the
  cache entry's flags, the span's head bytes: real work, not a narrow fill), the copper sky rows rewritten each frame
  (~0.01 Mc: the 3D view needs a clear) and the title's overlay (the flyby repaints under it).
- **Not done (they change the look or the data):** fewer faces on the 32X courses (merging coplanar strips, an LOD tile
  layer: the importer's job, local), a per-track draw distance cap for them (`ktrk_draw_r`, M5 finish: a reconvert), a
  span buffer against overdraw. The committed cart's cost did not move in M6 beyond the haze's +0.02-0.04 Mc.

Before / after per stage, as asked (frame_cost, plain twin): collect (`project.build`) loses the misaligned store's trap
(-0.04 Mc on Glacier's grid, -0.24 on DXFOREST's, model; ~0.19 Mc on the board for the 32X courses); the HUD stage loses
its whole-line reprints (~0.01 Mc); visibility, sort and fill are unchanged; the haze adds one LUT load a polygon in
collect (+0.02-0.04 Mc when on) and its shadow guard is compiled out when there is no pool. The fps table below was
taken before cut 1 (it moves the 32X cells by ~0.2 Mc, our tracks' by ~0.04).

## 3. The A/B keys (one table; the in-cart help line already names the first six)

The bench view's bottom line is `3-8 R  F FILL  M MUL  G F32  D DECAL  O OSD` (unchanged: it is in the title and
benchmark pins). Every key, from any non-menu screen (a debug key leaves the title / select first):

| key | what it switches | default | notes |
|---|---|---|---|
| `3`-`8` | draw distance R (tiles) | 8 (bench laps pin 5) | the options screen's DRAW DISTANCE; a track's mood may cap it |
| `f` | fill: CPU word stores / CHISEL AFFINE spans | CPU in the cart's state, AFFINE chosen on the board (M1) | byte-identical views (gated) |
| `m` | `mulsh16`: the ZM-X instruction / the plain 64-bit twin | instruction | same pixels; frame_cost runs the twin |
| `g` | the vertex transform in f32 (the FPU) | off | slightly different pixels; the f32 A/B |
| `d` | decals (faces' inner faces) | on | |
| `o` | the OSD: per-stage microseconds, fps | off | `u` the cart-only rate |
| `c` | the view CRC every 60 frames | on | ~0.5 Mc in the frame that reads it |
| `i` | shading FLAT / LIT / SOFT | FLAT | the options' SHADING |
| `y` | the shadow REAL / checkerboard | REAL | the options' SHADOW |
| `q` | the horizon haze on / off | on (a track with one) | M6; the options' HAZE |
| `v` | the POV far / near / cockpit | far | race, drive |
| `t` | the next track | | `l` the flyby, `A`-`H` a fixed pose, `p` pause |
| `b` / `x` | bench lap v1 (one car) / v2 (the race) | | R 5 pinned |
| `e` / `n` | the race / driving | | `s` start, `a` the recorded driver, `w` warp, `r` again |
| `z` / `h` / `j` | music / effects / the bench laps' audio | on / on / off | |

**A split-plane HUD, for the record: not built.** A HUD plane would cost ~0.59 Mc of FRESCO compositing a frame plus
~0.11 Mc a frame (CLAUDE.md, the 23 Oct refit) for two 8-row text lines that change about once a second; the band
redraw it would replace costs ~0.01 Mc (present.finish, both race lines + the minimap). On our tracks the race grid is
1.6-1.8 Mc without the I$ term: a plane would push every race frame past the board's 60 fps band (1.75-2.1 Mc). It
would also need a second page pair (HUD planes flip with the view) and the copper sky on another plane.
