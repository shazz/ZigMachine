# Kestrel Racing: the board batch (R82, 27 Nov)

Matt tested the local "RACER 32X MUSIC" card on KESTREL and listed bugs and missing features. All of them are on branch
`feat/racer-board-batch` (from `fix/racer-realtime`); the gate is `./build.sh --only racer`, the new harness
`apps/harness/racer_batch.mjs` (5 checks, 5 `--break` mutants) plus `racer_look.mjs --break pixel`. Cards:
`prototypes/cards/build_racer_batch.sh` stages `batch` (public) and `batchx` (LOCAL: the 32X data + `-Dracer_music`).
Nothing decoded from the 32X ROM is committed: only importer code (`vr32x_car.py` writes the class tag, `vr32x_look.py`
the PIXEL flag).

**Cart RAM** (the shelf disk had 1 KB over the library's 64 KB reserve with all five tracks: GLACIER is refused NO RAM
past it). The batch takes none of it: the per-frame scratch (the course model's polygons, the posed wheels) is carved
out of the library's stage buffer (used only while a file is read, between frames: `setup.scratch`); the wheel groups
are 30 bytes a model (a vertex's group comes from its position); the select's previews and the new course models are
carved per LISTED track at the scan instead of 16 static previews (9 KB). Shelf disk: 5 tracks, 68 KB free after the
library (65 KB before the batch); the zero-filled statics stay under `zero_segments`' 64 KB.

New keys: `]` / `[` the car; `_` the effects' PSG layout (harness); `--break` keys `&` (wheels still), `~` (old near
camera), `*` (models never turn), `<` (no bench HUD), `>` (tag class ignored), `|` (PIXEL ignored).

Not done / open: the board numbers (fps of the course select with a 32X model, BARD load of the PSG layout) are to be
measured on the board; the course model is a coarse height field (12 x 12), not the course's own faces (those would need
the track loaded: the cursor would cost ~0.5 s a move on the board).
