# The MP3 PLAYER's test files

CC0: synthesised by `make.sh` here (saw-wave chords, an arpeggio and noise hits; no recording, no
sample), encoded by LAME through ffmpeg's libmp3lame, with an ID3v2.3 title and no Xing frame.
Committed as encoded, so the pins never depend on an encoder version.

| File | Stream | Frames | What it proves |
|---|---|---|---|
| `TONES44.MP3` | MPEG-1 44.1 kHz stereo 128 kbps, 8 s | 308 | the bit-exact path (`apps/harness/mp3_check.mjs` exact), several 32 KiB reads |
| `MONO44.MP3` | 44.1 kHz mono 64 kbps, 4 s | 155 | mono: both sides the same, bit-exact |
| `TONES32.MP3` | 32 kHz stereo 96 kbps, 4 s | 113 | the linear rate conversion up to 44.1 |
| `TONES48.MP3` | 48 kHz stereo 128 kbps, 4 s | 168 | the linear rate conversion down to 44.1 |
| `LSF22M.MP3` | MPEG-2 22.05 kHz mono 64 kbps, 3 s, a 1000 Hz sine | 117 (576 samples each) | the recommended low-cost soundtrack format: an exact x2 to 44.1 |
| `LSF22S.MP3` | MPEG-2 22.05 kHz stereo 96 kbps, 1000 Hz left, 1500 Hz right | 117 | stereo LSF |
| `LSF24M.MP3` | MPEG-2 24 kHz mono 64 kbps | 127 | linear conversion up |
| `LSF16M.MP3` | MPEG-2 16 kHz mono 48 kbps | 86 | linear conversion up |
| `LSF11M.MP3` | MPEG-2.5 11.025 kHz mono 32 kbps | 60 | the MPEG-2.5 header, an exact x4 |

The `LSF*` files are pure sines (so the check can read the pitch back), self-generated by `make.sh`
(licence: self-generated, CC0), checked by `apps/harness/mp3_lsf.mjs`; they are not on the C: image.

They are on `docs/mp3-c.img` (`tools/mp3_c_image.py`) under `HD/MUSIC/`, which is `C:\MUSIC`.
Real music for listening tests stays local (never committed): `prototypes/mp3_card/HD/MUSIC/`.
