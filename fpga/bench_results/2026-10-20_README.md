# 2026-10-20: same-day baseline, the combined bitstream (queue + line-major + W64), the read-bypass budget

Board measurements over the serial console only (bench_collect.py, board_fps.py, a fps trace), nobody
at the keyboard, no sim. Every arm boots the same way (prototypes/chisel_queue_re/tools/boot_arm.py):
Linux reboot -> U-Boot, the PL loaded, the AFI widths as the card's boot.scr sets them (HP1 0xF00 = W64
from the first write), then boot.scr's Linux lines. The arm's own files are bind-mounted from board RAM
over the card's shelf (arm_shelf.py), so the SD card is never written. Glass: the rootfs's /usr/bin/glass
(82376563) in every arm. Shelf: the card's 103 disks (the 99-103 carts were not on the card yet).

**Full shelf** (108 disks, 103 in common with the baseline; all 108 running, none stalled or trapped): 98 within
+-1 fps, 2 faster (stniccc +7.8, polkadots +1.2), 3 slower. larcociel5 (-6.2) is not a regression: its disk was
replaced on the card between the runs (traced on both arms: 28.4 vs 28.5). **Two real regressions, both in the
system firmware, not the RTL:**

| cart | base | combo | cart_c base -> combo |
|---|---:|---:|---:|
| rno_natrium | 60.2 (70 s trace, flat) | 55.1 (51.5-59.8) | 0.69 -> 1.37 Mc |
| union_l16 | 37.5 avg (36.1 steady) | 32.4 avg (30.5 steady) | 1.06 -> 1.44 Mc |

Isolated on the lm8 bitstream (the card's), one system.rv32 swapped at a time (traces/lm8_*): this tree's firmware
d536048c reproduces both regressions on lm8 (rno 54.1, l16 30.6 steady); origin/main a9a032eb's firmware built
here (f6f844d0) does not (60.2 / 36.1); this tree's firmware with HOST_CHISEL_SYNC compiled out of every env entry
still regresses (54.0 / 30.7), and so does it with main's machine-video.wasm (54.0 / 30.8). So: not the RTL, not
the per-entry lazy-wait check, not the machine's QUEUE code; it is in the rest of perf/chisel-async's firmware
(bchisel.c / bblit.c / bdinval.h / bmain.c / host_split.py) or a layout effect of it. rno_natrium does no blits at
all (perf_audit: 53 KB of VRAM stores a frame), so the extra ~0.68 Mc is the CPU's own stores or fetches getting
slower. Next: bisect perf/chisel-async's firmware commits (7740706e, 46b6054e, 70f31dc2, e8237328) on lm8 with
these two carts (one build + two 40 s traces each, no Vivado).

## Read bypass (step 3): the budget, and why it was not built

perf/ziggy-read-bypass measured +108 LUT on the posted tree (15,045 -> 15,153; its own estimate ~+265 with margin),
sys WNS +0.074. On the combined tree that is ~15,400-15,557 LUT (87.5-88.4 %), and the combined build already sits
at sys WNS +0.041 ns, the thinnest margin of any board build so far (lm8 +0.043). A merge is clean
(perf/chisel-queue-bypass 07b5cdde: only decisions.md conflicts), but its Vivado run died in synthesis (the box
ran out of memory: global OOM kills at 20:0x, free 0.5 GB, 37 min elapsed) and was not retried.
Measured value of the bypass on 10-19: mc.lib.64K x1.11 and one cart faster (stcs 31.5 -> 36.4); stcs is now
57-60 fps from its own CHISEL rewrite. Recommendation: do not add it now; revisit with a LUT diet (blitter
steppers, PERFORMANCE_REVIEW refused/deferred list) if a cart proves read-after-store bound.
