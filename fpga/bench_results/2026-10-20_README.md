# 2026-10-20: same-day baseline, the combined bitstream (queue + line-major + W64), the read-bypass budget

Board measurements over the serial console only (bench_collect.py, board_fps.py, a fps trace), nobody
at the keyboard, no sim. Every arm boots the same way (prototypes/chisel_queue_re/tools/boot_arm.py):
Linux reboot -> U-Boot, the PL loaded, the AFI widths as the card's boot.scr sets them (HP1 0xF00 = W64
from the first write), then boot.scr's Linux lines. The arm's own files are bind-mounted from board RAM
over the card's shelf (arm_shelf.py), so the SD card is never written. Glass: the rootfs's /usr/bin/glass
(82376563) in every arm. Shelf: the card's 103 disks (the 99-103 carts were not on the card yet).

system while Matt was using the board. The board was put back on the card image at once (`boot`).

## Read bypass (step 3): the budget, and why it was not built

perf/ziggy-read-bypass measured +118 LUT on posted alone (15,035 -> 15,153; its own estimate ~+265 with margin),
sys WNS +0.074. On the combined tree that is ~15,410-15,557 LUT (87.6-88.4 %), and the combined build already sits
at sys WNS +0.041 ns, the thinnest margin of any board build so far (lm8 +0.043). A merge is clean
(perf/chisel-queue-bypass 07b5cdde: only decisions.md conflicts), but its Vivado run died in synthesis (the box
ran out of memory: global OOM kills at 20:0x, free 0.5 GB, 37 min elapsed) and was not retried.
Measured value of the bypass on 10-19: mc.lib.64K x1.11 and one cart faster (stcs 31.5 -> 36.4); stcs is now
57-60 fps from its own CHISEL rewrite. Recommendation: do not add it now; revisit with a LUT diet (blitter
steppers, PERFORMANCE_REVIEW refused/deferred list) if a cart proves read-after-store bound.
